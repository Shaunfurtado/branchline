# Canonical judge demo

Target runtime: 5–7 minutes for an interactive judge walkthrough. Prefer the live app at https://branchline-flax.vercel.app/?fresh=1, or run locally. Use a current Site-tools-compatible browser when demonstrating the agent path, 1920×1080 when possible, and always open with `?fresh=1`.

Paste-ready short instructions for Devpost: [`../submission/testing-instructions.md`](../submission/testing-instructions.md).

## Preflight

1. Open the live URL with `?fresh=1`, or run `npm install && npm run build && npm run preview` and open the preview URL with `?fresh=1`.
2. Confirm the command bar shows **Site tools: 6 registered** when WebMCP is available, or the human-mode fallback notice when it is not.
3. Open **Agent Capability Surface** briefly and confirm the discovered set matches the registered tools (or the unsupported state).
4. Close the dock. Keep cinematic audio muted unless the venue permits it.

## 1. Observe the healthy twin

Point out:

- one shared Asterion Mobility reality;
- healthy supplier flows;
- no recovery futures;
- six inspection capabilities only;
- synthetic-data disclosure.

Do not spend more than 15 seconds here.

## 2. Trigger the featured supplier shock

Click **Trigger featured supplier shock**.

Wait for the radial wave and red causal propagation. State the computed headline:

```text
16 affected orders
2 critically constrained plants
$28.43M exposed revenue
48,300-cell near-term shortfall
```

Open the Capability Dock long enough to show `create_branch` appearing.

## 3. Give the browser agent the canonical prompt

Use the in-app copy control and paste:

> Inspect the active disruption. Protect every Tier-1 customer and keep incremental cost below $300,000. Never use Voltra V-2170 cells in ORION-X. Create and simulate three materially different recovery branches, compare them, recommend one, and stage it for approval. Do not execute any operational change until I approve it in the BRANCHLINE interface.

The expected semantic investigation is snapshot, impact trace, constraints, substitutes, branch creation, simulation, comparison, explanation, and stage. Let the agent choose its exact valid order.

During calls, keep the application visible. Point out that inspections focus entities and traces animate causal paths; they are not toast-only events.

## 4. Show Branchspace

When three current branches are simulated, show the futures origin and T+0/T+7/T+14/T+30 snapshots. Contrast:

- Service First: all orders on time, highest cost/emissions;
- Cost Guard: cheapest service tradeoff and Apex initially at risk;
- Balanced Recovery: stronger protected-revenue/cost compromise.

Metrics must be read from the current cards, not memorized.

## 5. Change shared reality as a human

Select `order_1082` and click **Protect this order**.

Pause on:

- gold human seal;
- gold upstream dependency wave;
- context version increment;
- all old branch cards marked stale;
- `stage_plan` and `apply_plan` absent;
- event stream entry **Human changed shared context**.

Tell the agent:

> I just protected the Apex Health order in the interface. Re-read the shared constraints and re-simulate your recommended branch.

Show the recomputed balanced branch. Verify Apex is projected on time and that a lower-priority order carries the delay.

## 6. Stage and approve

Let the agent call `stage_plan`.

On the approval surface, point out:

- current branch/context versions;
- exact simulation hash;
- incremental cost;
- revenue protected;
- on-time/delayed counts;
- compatibility and human-intent checks;
- top actions and reversibility;
- the message that `apply_plan` is not registered.

Click **Approve and unlock execution** yourself.

Open the Capability Dock or watch the command bar as `apply_plan` registers. Note that no WebMCP tool can create approval.

## 7. Commit and verify

Tell the agent:

> The staged plan is approved. Apply it, verify the result, and explain why you split the battery order.

The agent should call `apply_plan`, then `verify_plan`, then `explain_tradeoff`.

Show the verified result:

- more than 90% of exposed revenue protected;
- cost below $300,000;
- one delayed lower-priority order in the featured run;
- zero hard violations;
- Apex on time;
- one exact human approval;
- one checkpoint.

## 8. Causal Proof

On the proof view, walk through:

```text
Nori outage
→ battery shortfall
→ ORION thermal class
→ Voltra incompatibility
→ scarce compatible supply
→ Helix allocation/inventory transfer
→ Apex protected
→ lower-priority counterfactual
```

Emphasize that these steps come from simulation evidence and action data, not an embedded LLM.

## 9. Rollback

Ask:

> Restore the checkpoint because the supplier agreement was not signed.

Show the rewind, restored reality label, ROLLBACK phase, and retained execution/rollback events. Confirm planning capabilities remain context-appropriate and no historical audit entry is removed.

## 10. Reset

Click **Reset**. Confirm healthy state, no branches, no approval/checkpoint, and six base tools.

## Failure recovery

- If WebMCP is unavailable, keep the human product demo running and state the browser limitation accurately. Do not use the local harness as though it were an external agent.
- If a simulation is stale, re-read constraints and re-simulate; never force staging.
- If the browser agent chooses Resilience rather than Balanced, accept it if it is current, valid, under budget, and Apex-safe; narrate the actual tradeoff.
- If audio is distracting, leave it muted. It is not required for any evidence.
